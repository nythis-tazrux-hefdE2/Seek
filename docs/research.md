# 从研究任务到 HTML 报告

本页面向研究使用者。开始前先完成[部署与模型/搜索配置](deployment.md)，确认账号可以进入研究页面。一次研究应有明确问题、事件时间窗口和可接受的来源范围。

## 定义并提交任务

首页可插入研究任务模板。用具体名称和日期替换模板内容，例如：

```text
主题：比较 LangGraph 与 AutoGen 的持久化与人工介入机制。
事件/版本时间窗口：填写明确的起止日期，或先让助手确认“最近 90 天”的具体范围。
来源要求：优先官方文档、发布说明和原始论文；第三方材料用于补充或交叉核对。
交付：两项独立并行调研、精确结果回收、另一会话独立核查、正式 HTML 报告。
未知：日期、版本和关键数字无法核实时保留未知，不用页面日期替代事件日期。
```

打开会话后可附加材料。发送时输入、幂等键与附件引用被冻结；恢复或重试应沿原提交操作。资料中的描述是研究材料，不授予模型访问其他用户文件或会话的权限。

## 查看过程与干预

默认领域 Skill 规定根会话先派发至少两项独立调研，回收精确任务结果，再交给另一个会话核查。过程视图展示模型、工具和子任务；模型可能因证据不足而补查或请求澄清。

需要回答或审批时使用对应界面，等待人工回答/审批时不能发送普通消息。取消一轮只影响指定 Turn；停止整树会终结该树的任务。刷新和断线恢复从持久状态与 SSE 继续展示，断线本身不等于任务失败。普通后续输入按队列处理，不能把另一轮研究的结果当作本轮证据。

## 阅读、下载与复查

正式报告卡片提供 HTML 预览与下载，包含摘要、范围、发现/对比、证据、冲突/未知和来源列表。日期区分事件、页面和系统获取时间；无法确认的值显示未知。

先核对研究范围，再阅读关键证据和核查分歧。正式检查只证明任务、来源和字段的一致性，不能替代人的事实判断。检查失败时助手需要补查或修正；普通 HTML 文件不自动成为正式报告。修改文件后不能继续沿用原检查结果，预览和下载会核对已登记内容哈希。

研究会话及反馈可在刷新后回读。Dashboard 的实测用量、估算、缺失与不完整记录各有含义，不把它们直接等同于供应商账单。

## 报告证据与完整性边界

正式报告采用本轮协调任务实际派发并成功完成的调研结果；其他研究、旧任务、失败或取消任务不能提供本轮证据。两项调研来自不同子会话，独立核查来自另一子会话，并保留核查指出的冲突与未知。

直接摘录必须与取得的连续原文一致，搜索片段不能充当正文。系统保留来源身份、获取时间、页面日期和证据类型；事件日期无法确认时保留未知，不能以页面日期代替。

正式报告生成成功后，系统登记检查结果与内容哈希。预览、下载和文件读取会复核登记信息及哈希；未登记或已被改动的 HTML 不能冒充通过检查的正式报告。

这些检查证明任务、来源和文件的一致性，不证明来源或核查结论必然正确。读者仍需根据原始材料判断事实、时间范围和结论适用条件。
